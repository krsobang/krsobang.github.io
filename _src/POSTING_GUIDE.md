# krsobang.github.io 게시 규칙 (자동 실행용)

## 매 실행 순서 (평일 1회)
1. `_src/state.json`과 `_src/log.md`를 읽는다.
2. **법령 변경 확인** — 공식 원문만 사용:
   - 국가법령정보센터(law.go.kr): 소방시설법, 화재예방법, 소방시설공사업법, 위험물안전관리법(각 시행령·시행규칙), NFPC·NFTC 전체, 소방시설의 내진설계 기준
   - 소방청 누리집의 공지사항·법령/고시 게시판, 국립소방연구원 NFTC 공고(사용자 PC 내장 브라우저로 열람; 못 열면 log.md에 "확인하지 못함"으로 기록하고 추측하지 않는다)
   - law.go.kr은 웹 조회(WebFetch)로 본문이 안 읽히므로 사용자 PC의 브라우저(내장 브라우저 우선, 안 되면 Chrome 확장)로 연다.
   - `state.json`의 `known_versions`와 공고번호·시행일을 대조한다.
3. **오늘(KST) 날짜의 글이 이미 있으면** 게시하지 않고, 확인 결과만 `log.md`에 기록한다.
4. **법개정이 있는 날** → 그 개정 1건을 글로 쓴다.
   - 「소방시설의 내진설계 기준」 개정 → `소방 내진개정` 카테고리, 그 외 소방 법령·NFPC·NFTC 개정 → `소방 법개정` 카테고리.
   - **사용자에게 브리핑**: SendUserMessage로 먼저 알린다 — 기준명·공고번호·시행일, 바뀐 조문의 변경 전/변경 후 문구(추가·삭제 부분 표시), 개정이유 한 줄, 경과조치, 현장 영향 한 줄. 브리핑과 별도로 글도 게시한다.
   - 하루에 개정이 여러 건이면 영향이 큰 1건을 게시하고 나머지는 브리핑에 목록으로 알린 뒤 다음 날부터 차례로 게시(state.json `pending_changes`).
   **법개정이 없는 날** → `state.json`의 `topic_rule`대로 `교육 및 해설서` 1편: 소방설비 풀과 내진설비 풀을 하루씩 번갈아, 풀 안에서는 무작위, `posted`와 중복 금지.
   내진설비와 소방설비는 한 글 안에서 주제·그림을 섞지 않는다.
   `소방시설 지침`은 정기 실행에서 자동으로 고르지 않는다(공문 지침 전용, 아래 '지침 글' 참고).
   이미 쓴 주제(`posted`)와 같은 사안이면 새 글 대신 기존 글을 수정한다.
5. **검증이 끝나지 않으면 공개하지 않는다.** 원고는 `_src/drafts/`에 두고 log.md에 미확인 사유를 적는다(추측 금지).
6. `python3 _src/build.py` → 커밋 → push → 공개 URL을 브라우저로 열어 본문·이미지 로딩 확인 → log.md에 결과 기록 → push.

## 글 양식 (2026-11-09 확정: "C 수정안")
본문은 모두 HTML 글로 직접 작성하고, 그림만 PNG로 첨부한다. 3~5분 안에 읽히게 짧게.
meta 필드로 상단을 만든다(build.py가 자동 배치):
- `effective`(칩: 시행일 또는 적용 기준), `subtitle`(조문·공고번호), `oneline`(한 줄 요약, 빨간 줄 박스), `why`(왜? 한 문장)
- `tile1~3`: "라벨|큰 값|작은 설명" 숫자 타일 3개
- `summary`(목록용), `tags`(해시태그), `ai_images: true`

### 법개정 글 본문 순서
1. 변경 비교표: 조문 | 변경 전(판본·시행일) | 변경 후 — 추가 문구는 `<span class="red">`, 변경 칸 `td.chg`
2. 개정 이유: 법제처(국가법령정보센터) 제·개정이유 원문을 `<div class="rule">`에
3. 적용 흐름: 타임라인(`.tl .st .dot`, 시행일은 `.st.now`) + 경과조치 문장
4. 그림으로 보기: 변경 전·후 비교 그림, 현장 입체 개념도, 조문 원문 이미지는 `<details>`로 접기
5. 현장 체크 표(설계·시공·감리·유지관리·점검)
6. 자주 묻는 것: `<details>` 문답 2~3개
7. 같이 보는 기준, 공식 원문 링크(현행·개정 전·관련 기준)
- 개정 전·후 판본 본문을 전체 대조해 바뀐 조문을 모두 확인한 뒤 쓴다.

### 소방시설 지침 글 (2026-11-10 신설: 공문 지침 전용)
- 대상: 법개정과 별도로 소방청·시도 소방본부·소방서가 공문(시행문)으로 안내한 지침·알림.
- 출처: 사용자가 준 공문 PDF, 또는 소방청·소방본부 공식 누리집에 게시된 공문만. 찾아서 임의로 만들지 않는다.
- 공문 원본 이미지를 직인 포함해 그대로 넣는다(페이지 단위 PNG). 바꾸는 것은 개인정보 가림뿐: 담당자·결재자 이름, 전화·팩스, 이메일을 회색 상자로 가리고 "개인정보 가림"이라고 적는다. 직인을 그리거나 합성·재현하지 않는다.
- 본문 순서: ① 공문 요약(발신·문서번호·시행일자·제목) ② 공문 원본 이미지 ③ 핵심 내용 정리 ④ 그 뒤 실제 법령 반영 여부(국가법령정보센터로 확인, 확인 못 하면 "확인하지 못했다") ⑤ 현장 체크 ⑥ 출처.
- 정기 실행에서 공문 PDF가 `_src/inbox/`에 있으면 그날 해설 대신 그 지침을 1편 게시하고 파일은 `_src/inbox/done/`으로 옮긴다.

### 교육 및 해설서 글 본문 순서 (기준 조문 해설)
1. 공식 기준 원문(핵심 조항 `<div class="rule">` 빨간 테두리)
   - 바로 아래에 **원문 화면 사진**: 국가법령정보센터 해당 조문 화면 캡처 + 관련 별표 이미지 캡처. 캡션에 출처·캡처일·고시/공고번호.
2. 적용 조건
3. 그림(상세도·확대도·입체 개념도)과 측정 기준점 주의
4. 단계별 확인사항 표
5. 적용 시점과 경과조치(연혁 대조)
6. 공식 원문 링크

### 그림 방식 (2026-11-11 변경: 3D 실내 장면)
- 입체 그림은 three.js 장면으로 만든다: spec.json 작성(예시 `_src/fig3d/examples/beam.json`) → `python3 _src/fig3d/render.py spec.json out.png` → `assets/img/<날짜-slug>/figN.png`.
- 밝은 실내, 보(진한 청회색)와 천장 슬래브(연한 청회색) 구분, 실물 형상의 헤드·감지기·유도등·송수구 등, 남색 이름표, 빨간 치수 화살표. 헤드·감지기는 `"s"`(배율, 헤드 2.6·감지기 2.2 권장)로 크게 그린다.
- **배관·행거봉은 보를 관통할 수 없다.** 주배관·가지배관은 보 하단보다 아래(보 밑)로 지나가게 그린다(예시 beam.json: 배관 높이 < 보 하단 높이). 헤드는 배관에서 아래로 매달고, 행거봉은 보 바깥에서 슬래브로 올린다. render.py가 겹침을 검사해 위반하면 렌더를 중단한다(종료 코드 2).
- **반자(천장 마감)가 없는 노출 천장의 헤드는 상향식(`head_upright`)으로 그린다.** 하향식(`head_pendent`)은 신축배관(플렉시블 호스, `flex` 타입)으로 가지배관에 연결한 모습으로만 그린다(예시 `examples/flex.json`). (2026-11-11 사용자 지시)
- 가지배관은 주배관과 티(Tee)로 이어지게 그리고(예시 `examples/beam.json`), 행거봉은 보 바깥에서 슬래브로 올린다.
- 이름표끼리 겹치지 않게 dx/dy를 조정하고, 렌더 결과 PNG를 직접 열어 확인한 뒤 쓴다.
- 기존 SVG 방식은 평면 표·타임라인·단순 도식에만 쓴다.

### 공통
- 그림은 공식 기준에서 확인한 거리·관계만 표시. "AI 작성 비축척 개념도"와 생략 항목 명시.
  천장(밝은 베이지·슬래브 단면 사선 해칭)과 보(진회색·반대방향 해칭)를 확실히 구분하고 면 이름표를 붙인다.
- 조문 원문 이미지를 만들 때 화면 캡처가 아니면 "원문 문구를 그대로 옮긴 이미지(화면 캡처 아님)"라고 밝힌다.
- 원문 표현과 해석을 구분("원문은 ~", "일반적 해석", "(의견)"). 확인 못 한 것은 "확인하지 못했다"고만 적는다.
- 조문·고시 번호, 질의회신, 수치는 원문에서 확인한 것만. 기억으로 쓰지 않는다.

## 제목
- state.json `title_hint`에 주제별 제목 초안이 있다. 원문 확인 결과와 맞지 않는 표현(수치 등)이 있으면 고쳐 쓴다. 제목은 질문형·실무형으로, 확인하지 않은 수치를 넣지 않는다.

## 네이버 블로그 병행 (2026-11-09 추가)
- build.py가 글마다 `naver/<slug>.html`(네이버 복사용 페이지, noindex)을 자동 생성한다. 서식은 모두 인라인 style.
- 네이버는 Claude가 직접 올릴 수 없으므로, 매일 보고에 **네이버 복사용 링크**(https://krsobang.github.io/naver/<slug>.html)와 네이버 카테고리명을 함께 보낸다. 사용자가 ① 제목 복사 ② 본문 복사 → 네이버에 붙여넣고 발행한다.
