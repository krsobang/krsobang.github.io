# krsobang.github.io 게시 규칙 (자동 실행용)

## 매 실행 순서 (평일 1회)
1. `_src/state.json`과 `_src/log.md`를 읽는다.
2. **법령 변경 확인** — 공식 원문만 사용:
   - 국가법령정보센터(law.go.kr): 소방시설법, 화재예방법, 소방시설공사업법, 위험물안전관리법(각 시행령·시행규칙), NFPC·NFTC 전체, 소방시설의 내진설계 기준
   - 소방청 고시·공고, 국립소방연구원 NFTC 공고
   - law.go.kr은 웹 조회(WebFetch)로 본문이 안 읽히므로 사용자 PC의 브라우저(내장 브라우저 우선, 안 되면 Chrome 확장)로 연다.
   - `state.json`의 `known_versions`와 공고번호·시행일을 대조한다.
3. **오늘(KST) 날짜의 글이 이미 있으면** 게시하지 않고, 확인 결과만 `log.md`에 기록한다.
4. **법개정이 있는 날** → 그 개정 1건을 글로 쓴다.
   - 「소방시설의 내진설계 기준」 개정 → `소방 내진` 카테고리, 그 외 소방 법령·NFPC·NFTC 개정 → `소방 법개정` 카테고리.
   - **사용자에게 브리핑**: SendUserMessage로 먼저 알린다 — 기준명·공고번호·시행일, 바뀐 조문의 변경 전/변경 후 문구(추가·삭제 부분 표시), 개정이유 한 줄, 경과조치, 현장 영향 한 줄. 브리핑과 별도로 글도 게시한다.
   - 하루에 개정이 여러 건이면 영향이 큰 1건을 게시하고 나머지는 브리핑에 목록으로 알린 뒤 다음 날부터 차례로 게시(state.json `pending_changes`).
   **법개정이 없는 날** → `state.json`의 `topic_rule`대로 지침 1편: `소방시설 지침`과 `소방 내진` 풀을 하루씩 번갈아, 풀 안에서는 무작위, `posted`와 중복 금지.
   내진설비와 소방설비는 주제·카테고리·그림을 섞지 않는다.
   이미 쓴 주제(`posted`)와 같은 사안이면 새 글 대신 기존 글을 수정한다.
5. **검증이 끝나지 않으면 공개하지 않는다.** 원고는 `_src/drafts/`에 두고 log.md에 미확인 사유를 적는다(추측 금지).
6. `python3 _src/build.py` → 커밋 → push → 공개 URL을 브라우저로 열어 본문·이미지 로딩 확인 → log.md에 결과 기록 → push.

## 글 양식 (2026-11-09 확정: "C 수정안")
본문은 모두 HTML 글로 직접 작성하고, 그림만 PNG로 첨부한다. 3~5분 안에 읽히게 짧게.
meta 필드로 상단을 만든다(build.py가 자동 배치):
- `effective`(칩: 시행일 또는 적용 기준), `subtitle`(조문·공고번호), `oneline`(한 줄 요약, 빨간 줄 박스), `why`(왜? 한 문장)
- `tile1~3`: "라벨|큰 값|작은 설명" 숫자 타일 3개
- `summary`(목록용), `tags`(해시태그), `ai_images: true`

### 법개정 글 본문 순서
1. 변경 비교표: 조문 | 변경 전(판본·시행일) | 변경 후 — 추가 문구는 `<span class="red">`, 변경 칸 `td.chg`
2. 개정 이유: 법제처(국가법령정보센터) 제·개정이유 원문을 `<div class="rule">`에
3. 적용 흐름: 타임라인(`.tl .st .dot`, 시행일은 `.st.now`) + 경과조치 문장
4. 그림으로 보기: 변경 전·후 비교 그림, 현장 입체 개념도, 조문 원문 이미지는 `<details>`로 접기
5. 현장 체크 표(설계·시공·감리·유지관리·점검)
6. 자주 묻는 것: `<details>` 문답 2~3개
7. 같이 보는 기준, 공식 원문 링크(현행·개정 전·관련 기준)
- 개정 전·후 판본 본문을 전체 대조해 바뀐 조문을 모두 확인한 뒤 쓴다.

### 지침 글 본문 순서
1. 공식 기준 원문(핵심 조항 `<div class="rule">` 빨간 테두리)
2. 적용 조건
3. 그림(상세도·확대도·입체 개념도)과 측정 기준점 주의
4. 단계별 확인사항 표
5. 적용 시점과 경과조치(연혁 대조)
6. 공식 원문 링크

### 공통
- 그림은 공식 기준에서 확인한 거리·관계만 표시. "AI 작성 비축척 개념도"와 생략 항목 명시.
  천장(밝은 베이지·슬래브 단면 사선 해칭)과 보(진회색·반대방향 해칭)를 확실히 구분하고 면 이름표를 붙인다.
- 조문 원문 이미지를 만들 때 화면 캡처가 아니면 "원문 문구를 그대로 옮긴 이미지(화면 캡처 아님)"라고 밝힌다.
- 원문 표현과 해석을 구분("원문은 ~", "일반적 해석", "(의견)"). 확인 못 한 것은 "확인하지 못했다"고만 적는다.
- 조문·고시 번호, 질의회신, 수치는 원문에서 확인한 것만. 기억으로 쓰지 않는다.

## 금지
- 운영자의 소속 회사명·관련 회사명·개인 이름·연락처·서명·자격번호·실제 현장정보를 어디에도 넣지 않는다.
- 비밀번호·토큰·쿠키를 출력하거나 파일에 저장하지 않는다.
- 무관한 기존 글 삭제 금지.

## 파일 구조
- `_src/posts/YYYY-MM-DD-slug.html` : 첫 줄 `<!--meta ... -->` (title, date, category, slug, summary, ai_images) + 본문 HTML
- 그림: `assets/img/YYYY-MM-DD-slug/figN.png`, 본문에서는 `../assets/img/...`
- 카테고리: 소방 법개정 / 질의·해석사례 / 소방시설 지침 / 각종서류 / 소방 내진
